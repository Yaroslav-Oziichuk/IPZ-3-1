# Самостійна робота №4 
**Тема:** Перевантаження конструкторів: приклади та сценарії

## Відповіді на контрольні запитання

1. **Навіщо потрібне перевантаження конструкторів у класі Product?**
   Перевантаження конструкторів дає гнучкість при створенні об'єктів. Залежно від наявних даних (наприклад, коли відомі лише назва і ціна, або ж повний набір характеристик товару), ми можемо зручно ініціалізувати об'єкт без потреби передавати зайві `null` чи дефолтні значення вручну.

2. **Чому конструктор копіювання зручно реалізовувати через `this(...)`?**
   Виклик основного конструктора через `: this(...)` дозволяє уникнути дублювання коду ініціалізації полів (дотримуючись принципу DRY — Don't Repeat Yourself). Уся логіка присвоєння значень залишається в одному місці — основному конструкторі.

3. **Які переваги дає read-only доступ до властивостей після створення об’єкта?**
   Read-only властивості забезпечують **незмінність (immutability)** об'єкта. Це гарантує цілісність даних: характеристики товару (ціна, ID, назва) не можуть бути випадково змінені ззовні після ініціалізації, що запобігає появі важковиявлюваних багів.

4. **У яких випадках перевизначення `ToString()` спрощує налагодження та демонстрацію роботи класу?**
   Перевизначення `ToString()` дозволяє виводити повну та зручно відформатовану інформацію про об'єкт просто передаючи його у `Console.WriteLine(product)` або під час відлагодження (debugging) у VS Code / Visual Studio, не вичитуючи кожну властивість окремо.
